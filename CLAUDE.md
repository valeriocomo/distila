# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Distila is a Chrome extension (Manifest V3) that summarizes the article on the current page using Chrome's **on-device Summarizer API** (Gemini Nano). No backend, no build tooling for the extension itself — `src/` is loaded directly as an unpacked extension. Node is only used for packaging/release scripts, not for running the extension.

## Commands

```bash
npm install        # also installs the husky commit-msg hook via "prepare"
npm run build       # zips src/ into extension.zip at project root (uses archiver, cross-platform)
npm run sync-version # copies package.json version -> src/manifest.json (runs automatically on `npm version`)
```

There is no lint or test suite in this repo.

### Manual release fallback

```bash
npm version patch   # or minor / major — also syncs src/manifest.json and stages it
git push --follow-tags
```

## Architecture

- **`src/`** is the actual extension package root (what Chrome loads via "Load unpacked" and what gets zipped for the stores) — not the repo root.
  - `manifest.json` — MV3 manifest, permissions: `activeTab`, `scripting`, `offscreen`, `sidePanel`, `storage`. No `default_popup`: the UI is the global side panel (`side_panel.default_path`).
  - `common.js` — helpers shared by the service worker (`importScripts`) and the panel (`<script>` before `sidepanel.js`): `jobKey`, `pageKey`/`samePage`, `isActiveJob`. It is a classic script, so its top-level names are globals in both contexts: never redeclare them there.
  - `sidepanel.html` / `sidepanel.js` — the side panel (one per window, global, **not** tab-specific) is a **view only**: it follows its window's active tab (`tabs.onActivated`/`onUpdated`, filtered by the window from `windows.getCurrent()`), extracts the page text, hands the job off, and renders that tab's job from `chrome.storage.session` (via `chrome.storage.onChanged`). Everything goes through `refresh()` → `render()`, which always starts from a blank view so nothing of the previous tab leaks. A tab without a visible `tab.url` has no `activeTab` grant (no `tabs` permission): the panel then asks the user to click the icon. Stored jobs match the tab by `samePage()` (URL without `#fragment`, except hash routes). A queued/running job of the page shows its position/progress and a **Cancel** button (`cancel-job` message with the job's `jobId`); tabs without their own job show how many jobs are active elsewhere. The same page is the popup fallback (`?mode=popup` → `body.popup` styles).
  - `background.js` — minimal coordinator service worker: opens the panel from `chrome.action.onClicked` with `chrome.sidePanel.open()` — called **synchronously first** (an `await` before it loses the user gesture) — and then messages the panel (`tab-access-granted`). **Never use `setPanelBehavior({ openPanelOnActionClick: true })`**: Chromium then toggles the panel without granting `activeTab` (crbug 40904917) and without firing `onClicked`; `onInstalled` pins it to `false` because the setting is persisted. `configureAction()` clears the popup, or sets `sidepanel.html?mode=popup` when `chrome.sidePanel` is missing; it re-runs on every worker start (MV3 `setPopup` isn't persisted). It also ensures the offscreen document exists (`chrome.runtime.getContexts` + `chrome.offscreen.createDocument`, one shared pending creation; before creating one, `markInterruptedJobs` turns stored queued/running jobs into errors, since a missing document means the previous one died with its queue), forwards `start-summarization` and `cancel-job` messages to it and relays its replies (`forwardCancel` never creates a document; if the document doesn't know the job, `removeIfActive` removes the stuck state), and persists the `jobs-update` batches it sends back into `chrome.storage.session` under one **`job:<tabId>` key per tab** (`writeJobs`: removals only delete a key still holding the same `jobId`; jobs of closed tabs are not stored but returned as `dropped`, and the offscreen document cancels them; `tabs.onRemoved` removes the key and cancels the tab's job). All its session-storage writes go through `withStorageLock()` — never await a message reply inside it, and it isn't reentrant (code under the lock calls the unlocked `writeJobs`/`markInterruptedJobs`). It mirrors each tab's job on the **toolbar badge**/tooltip (`showBadge`, only while `samePage(tab.url, job.url)`); Chrome clears per-tab action values on every cross-document navigation, so `tabs.onUpdated` (`complete` or `url`) and icon clicks re-apply it via `syncBadge`. It cannot call the Summarizer API itself (the API requires a document context, not a service worker).
  - `offscreen.html` / `offscreen.js` — the summarization pipeline runs here so it **survives the panel closing**, behind an in-memory **FIFO queue** (unlimited; one job runs at a time; the page text never leaves this document). Each job has a `jobId`; its state (`queued` with `position`, `running` with `progress`, `done`, `error`, plus `tabId`/`url`) is relayed to the service worker as `jobs-update { jobs, removed }` batches via `chrome.runtime.sendMessage` — **offscreen documents can only use `chrome.runtime` messaging, no other extension APIs** (`chrome.storage` is undefined there). Queue invariants: `current` (the running slot) is always live — aborting it hands the slot over in the same synchronous step; aborted/replaced entries are muted (`update`/`finish` ignore them); every outgoing message goes through the `outbox` chain, in order; `finish` frees the slot before sending, so a simultaneous cancel finds nothing. A new request from a tab replaces that tab's queued job in place, or aborts its running job and takes over the slot. Cancelling aborts the job's `AbortController` (its `signal` goes to every `create()`/`summarize()`/`translate()`/`detect()`) **and** `destroy()`s its tracked sessions (on Chrome 138 an aborted call doesn't stop the model); cancellation is detected via `signal.aborted`, never the error type, and the catches that swallow errors (language detection, translation fallbacks) rethrow when aborted. Start/cancel replies are sent once the new state is stored. Messages are routed by a `target` field (`'background'` / `'offscreen'` / `'sidepanel'`).
- **Text extraction**: `sidepanel.js` injects `extractArticleText()` into the active tab via `chrome.scripting.executeScript`, relying on `activeTab` only (no host permissions): it is granted per tab by the click on the action, survives tab switches and same-origin navigations, and is lost on cross-origin navigation. Clicks inside the panel don't grant it. It tries `<article>`, then common content-container selectors, then falls back to `document.body`, using `innerText` to strip markup.
- **"Summary of summaries"** (in `offscreen.js`): for long articles (`articleText.length > CHUNK_SIZE * 1.2`, `CHUNK_SIZE = 3000` chars), `splitIntoChunks()` breaks text into paragraph/sentence-respecting chunks, `recursiveSummaryOfSummaries()` summarizes each chunk (`tldr`/`plain-text`/`long`) and recursively re-compresses the concatenated result until it's under the threshold. Only then is the final user-facing summary generated with the user's chosen `type`/`length`/`format` (markdown or plain-text).
- **Output language auto-detection** (in `offscreen.js`): `runJob` detects the article language once per page with the on-device **LanguageDetector API** and uses it as the Summarizer's `outputLanguage`. The result is relayed to the service worker (`language-detected` message) and cached in `chrome.storage.session` under `langByTab` (`{ [tabId]: { url, language } }`); the background attaches the cached value (`detectedLanguage`) when forwarding later `start-summarization` jobs for the same tab+url, and a `chrome.tabs.onRemoved` listener drops the entry when the tab closes. If the detected language is outside `SUPPORTED_OUTPUT_LANGUAGES` (`en/es/ja/de/fr`, further narrowed at runtime by `Summarizer.availability`), the job sets a `warning` field (rendered by the panel's `#warning` notice) and falls back to the **Translator API**: article → English (chunked), summarize in English, summary → detected language (line-wise for markdown to preserve structure). If the Translator pair is unavailable or fails, it summarizes in English anyway and keeps the warning.
- Everything is vanilla JS/HTML/CSS — no framework, no bundler, no TypeScript.

## Versioning & releases

- Version is tracked in `package.json` and mirrored into `src/manifest.json` by `scripts/sync-version.js` — never hand-edit the version in `manifest.json`.
- Commit messages **must** follow [Conventional Commits](https://www.conventionalcommits.org/) — enforced locally by a husky `commit-msg` hook running commitlint (`commitlint.config.js`), and relied on by release-please to compute version bumps and the changelog. If a PR is squash-merged, the **PR title** becomes the commit on `main`, so the PR title must follow the convention too.
- Releases are driven by [release-please](https://github.com/googleapis/release-please), configured via `.release-please-config.json` / `.release-please-manifest.json`. The `release-please` GitHub workflow only runs on manual `workflow_dispatch` — never automatically on push. It must be run once to open/update the release PR, and run again after that PR is merged to actually create the git tag + GitHub Release.
- `.github/workflows/publish.yml` builds `extension.zip` and publishes to the Chrome Web Store (and Edge Add-ons, currently disabled via `if: false` in the workflow) in parallel, then attaches the zip to the GitHub Release. It runs in two ways: dispatched automatically by the `release-please` workflow after it creates a release (tags created by release-please use the `GITHUB_TOKEN`, whose events never trigger other workflows — that's why the dispatch step exists), or on a manually pushed `vX.Y.Z` tag. It can also be re-run by hand via `workflow_dispatch` with the `tag` input (e.g. `v1.2.3`).
- First publication to each store must be done manually from the respective dashboard (Chrome Web Store Developer Dashboard / Edge Partner Center) to obtain the extension/product ID before the automated workflow can update it.
